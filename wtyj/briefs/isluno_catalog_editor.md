Issue: https://github.com/unboks-org/unboks-dashboard-api/issues/164. Backend issue base `92c9989fae5546986c89590ba78b2b050b2745ec`; dashboard issue base `2e41f4a209fbafc602419408696a25fa9791dc34`. This is one coordinated draft candidate across the two repositories. 8/14 previously accepted in candidate; 0 merged/verified. No release authority is requested.

The existing dashboard Trip & pricing entry now selects Isluno from authenticated server capabilities. `dashboard/isluno_catalog_api.py` adds GET/PUT `/isluno/catalog` and authenticated catalog JPEG preview, wired into the existing Isluno router and host `_check_auth`. Every operation also requires the literal enabled feature, active valid Isluno profile, Mermaid runtime/config identity and strict account setup. Request bodies cannot select a tenant or filesystem path. Capabilities report catalog_editor only when the existing strict feature is active; the unapplied feature patch stays off.

The API reuses `CatalogStore` directly: process lock, CAS revision check, full validation, historical snapshots, atomic writes and error distinctions (409 conflict, 422 validation, 503 unavailable). It adds no supplier or provider adapter. Gallery validation preserves imported content identity. A narrow publisher constraint preserves existing demo authority, label, approval reference and real-booking ineligibility; new rules get new sample versions. The UI keeps source/missing facts separate from demo rule forms and retains unsaved changes when a save fails.
