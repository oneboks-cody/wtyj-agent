# Evidence boundaries

The candidate remains an offline demo. No real booking, charge, message, email, provider lookup, runtime inspection, source refresh or number change was performed. All generated guests, histories and transport IDs are synthetic. The full runner and integrated exporter disable socket connect/connect_ex/sendto, create_connection and DNS before runtime imports. The synthetic transport has a hard ceiling of 100 posts and four emails; these are in-memory callbacks, not a paid allowance.

| Segment | Executed application code | Substitution / limit |
|---|---|---|
| WhatsApp entry | WhatsAppZernioChannel.from_zernio, actual social agent handler and Isluno routing | No external webhook HTTP signature/enqueue/worker entry. The existing test helper supplies a normalized provider envelope, synthetic account/timestamp and patched ignored-contact/auto-block boundary. |
| Understanding | Actual one-call understanding boundary, validation, reserve/apply, duplicate and action handling | Structured decision returned by a deterministic mock. No model request. Separate SDK-entrypoint tests use mocks, not native-language or live-model evaluation. |
| Catalog and pricing | Real versioned catalog, itinerary/pricing engines and immutable snapshots | Integrated stage fixture uses one synthetic product with explicitly labelled sample rules. Independently, the full suite prices all 31 committed real products, validates their unresolved supplier facts and every imported asset hash; it does not refresh the website. |
| Native actions | Actual summary confirmation, quote approval, simulated payment and exact-address consent handlers | Button payloads are read from real application jobs and returned through normalized inbound. No fixture advances new business stages. No external customer checkout/card form is involved. |
| WhatsApp delivery | send_reply → ZernioSender → discovery/quote/fulfillment senders, pacing, per-part claims and acceptance records | Store constructors bind disposable stores; post_once is replaced with a deterministic accepted/ambiguous callback. Window is synthetic open. Application callers write the acceptance ledger. Provider HTTP normalization, real control state and delivery/read receipts are not proven. |
| Email | Real consent ledger, fulfillment scheduling entry and send_pending_email claim/content/attachment flow | Thread scheduler runs inline for determinism, email_guard is fixture-true and transport records bytes in memory. No SMTP/provider call. Other tests cover asynchronous scheduling, control suppression, revoked/ambiguous consent and no replay. |
| Operator | Real Operations routes and exact host auth function; PDF bytes read through authenticated API | Synthetic token and TestClient, not outer login. New integrated records are API-inspected. Existing actual-shell desktop/mobile browser evidence at the unchanged frontend head is carried forward; no new browser run is claimed here. |
| Cutover and rollback | Actual transition.ensure, run_once feature rollback, sender fence and post-reactivation delivery callers | Six synthetic legacy tables seeded through actual schemas before cutover. All new journey/payment/document/consent/recovery records produced by handlers. No deployed configuration changed. Legacy inbound replay is separately covered by the accepted five-table rehearsal and recovery tests. |

Transport IDs mean only fixture acceptance, never delivered/read. Native carousels remain disabled; ordinary in-chat image pagination is the demonstrated contract. Native-language approval is pending separately from six-language structural/translation-copy tests (Papiamento is explicitly flagged). Current ownership and sole-consumer status of +1 223 276 0075 are unverified at this stage. Historical baseline reports are provenance, not present runtime authority.

No direct SQL in the integrated test sets a new itinerary paid, approves a quote, grants new email consent or marks a new delivery accepted. Its SQL writes seed only pre-existing legacy rows; subsequent ledger assertions are read-only. Other isolated unit/fault tests sometimes construct intermediate states; those are contract evidence, not substitutes for the integrated path.
